# 验证范围

## 0.5.14.dev3 上位机

打包后的连接测试使用普通 Windows 用户权限，调用上位机的连接流程，成功识别 `background-pc-rle7` 并通过 DRW1 读出 **480 × 320** 的完整首帧。交付 EXE 也通过离线启动检查。[机器可读摘要](../evidence/rle7-client-dev3-validation.json)

新版上位机在 rle7 的水平与垂直长按移动期间保留绘图流。回归模型使用 C 绘图发送端和 Python 客户端，验证松手前收到移位后的完整帧，并在松手后释放 M。两个方向的实机长按尚待验证。

## rle7 实机验证（2026-11-22）

运行组合为 `background-pc-rle7` 和 0.5.14.dev1。验证使用一台硬件 2.4、Bootloader 4.0、LCD 0x9488 的 DS100。153,600 个 RGB565 像素与参考读回一致，两个主频档共取得 42 轮有效计时，计划外重同步 0 次。[机器可读摘要](../evidence/rle7-validation.json)

采集空窗的计时区间为 **DMA 停止到下一次定时器触发放行**。同一固件的限时诊断用于比较原编码和发布版策略。下表的每个单元汇总 3 轮正常镜像观察。

| 主频和时基 | 原编码平均／最长 | 发布版策略平均／最长 |
| --- | ---: | ---: |
| 250 MHz，40 ns/div | 36.59 / 40.12 ms | 23.46 / 36.54 ms |
| 200 MHz，200 ns/div | 10.92 / 42.34 ms | 10.71 / 42.40 ms |

发布版在 250 MHz 稳定镜像的前三个正常帧完成后启用新编码。在 200 MHz、初始同步和重同步期间选择原编码。200 MHz 限用策略的诊断写入计数为零。全矩阵的最长空窗为 220.82 ms，出现在 200 MHz 强制重同步时，其中 LCD 读回约占 179.03 ms。

另一次 250 MHz 日常镜像持续 60.01 秒，交付 2,257 个完整帧（37.61 帧/秒），其中 1,601 帧波形区有变化，重同步 0 次。测试结束后采集继续运行，档位和触发设置已恢复，盘内四个用户文件哈希与升级前一致。

本节采集计时使用 0.5.14.dev1。当时 rle7 走兼容按键流程，实机测量未覆盖 M/E 快速组合路径。

此前研究环境完成 1,349 项离线检查，其中包含 ARM 指令模型和捕获绘图数据重放。公开仓库另有 279 项检查通过。独立漏触发率、绝对时基精度和长期稳定性仍待验证。

## B 站完整教程录制（2026-11-16）

[正式视频](https://www.bilibili.com/video/BV1tHsW6kEsE/)使用一台硬件 2.4、Bootloader 4.0、LCD 0x9488 的真实 DS100，组合为 R11 + 客户端 0.5.6.dev1。实机部分覆盖 M/E 菜单切换、四种保持组合、连续移动、双击 E 切换通道和保存 480 × 320 PNG。

本次成功录制记录 1010 个设备画面，连续移动交付 6 步，档位与偏移在结束时恢复。短录制中没有重同步，不代表长期或所有模式都不会暂停。录制过程中没有刷写固件。摘要见 [B站录制验证](../evidence/bilibili-validation.json)。

完整成片为 1920 × 1080 / 30 fps、本地时长 486.168 秒；B 站页面显示 487 秒。20 章均已完成，含三段实机演示。视频与音频完整解码、211 条字幕的时序及宽度、旁白响度检查通过；不宣称已经由真人试听验收。

## GitHub 早期教程录制

发布资产中的 `DS100-Remote-R11-Usage-1080p.mp4` 为早期约 4 分 12 秒教程，使用客户端 0.5.5.dev1。七段实机录制均通过菜单／位置／档位或文件结果检查，连续移动交付 11 步，录制后恢复原设置。该次录制有 1 次自动重同步，与上方 B 站录制是两次独立记录。

两版视频的鼠标事件均由程序内 Qt 自动化执行，轨迹和点击圈作为讲解提示。设备画面和响应来自实际 USB，不是模拟器。B 站版实机操作保持原速，没有加速设备响应。30 fps 是视频文件帧率，不是仪器新帧或采样率承诺。旁白为合成语音。

## R11 其他检查与限制

之前严格控制检查 7 项、非零偏移检查 8 项通过。保持组合可见反馈约 0.26–0.30 秒，M 菜单约 1.04–1.24 秒。R11 本轮以控制和菜单状态为主，未完成新的全模式逐像素比较。R10 菜单曾完成 153600 像素零差异比较。

原始 ARM 指令执行测试使用模拟的 USB/LCD/RAM 边界，不能替代物理设备验证。完整 MCU Flash／校准备份、正式回退、所有硬件版本、168 MHz USB 策略下的测量准确性和最高采集模式均未验证。原生实时采样与绝对运行／停止服务尚未绑定。

早期机器可读摘要见 [R11验证摘要](../evidence/r11-validation.json)，最新视频补录见 [B站录制验证](../evidence/bilibili-validation.json)。

客户端 0.5.6 增加连接前的物理 USB 身份核对和已打开句柄的磁盘绑定。错误身份的软件用例、普通用户下的真实 R11 INFO 与完整读屏均通过；本次 B 站补录也使用该客户端。

[脱敏软件检查报告](../evidence/tests-0.5.6.xml)保留测试名称与结果，不含主机名或原始控制台输出。独立复审通过，录屏工具还覆盖了慢请求下的退出重试和子编码器回收。

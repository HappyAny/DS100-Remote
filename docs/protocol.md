# DS100 Remote 协议 1

这是本工程新增的协议，原厂固件不实现它。所有多字节整数和浮点数按小端编码。
传输复用 USB MSC Bulk-Only Transport，由 Windows SPTI 发送 vendor SCSI CDB；没有安装替代 USB 驱动。
设备现有端点为 OUT `0x01`、IN `0x81`，最大包长 64 字节。

## 请求 CDB

固定 16 字节，Python 格式 `<BBBBIHHHH>`。

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | u8 | SCSI opcode `0xC0` |
| 1 | u8 | 子命令 |
| 2 | u8 | 版本 `1` |
| 3 | u8 | flags，必须为 `0` |
| 4 | u32 | 请求序号，回复必须相同 |
| 8、10、12、14 | 各 u16 | 参数 a、b、c、d |

所有命令通过 DATA-IN 取得回复；`SET_RUN` 也通过 CDB 参数表达控制动作。
Windows 传输层仅接受本协议的命令和头字段，不提供任意 SCSI 命令或磁盘写入接口。

| 命令 | 编号 | 参数 | 回复内容 | 原生候选 |
| --- | --- | --- | --- | --- |
| INFO | 1 | 全 0 | UTF-8 JSON | 有 |
| SCREEN_READ | 2 | x、y、宽、高 | 屏幕块 | 有 |
| WAVE_READ | 3 | 点数、通道掩码、样本偏移低 16 位、高 16 位 | 波形 | 未绑定 |
| SET_RUN | 4 | 运行=1 或停止=0，其余 0 | 同值 u8 确认 | 未绑定 |
| SCREEN_STREAM | 5 | x、y、宽、最多行数 | 完整行的 RLE 屏幕块 | 仅 R4 候选 |
| DRAW_PROFILE | 6 | action：0 停止、1 清零并开始、2 快照，其余 0 | 16 个 u32 统计字段 | 仅 R5 分析候选 |
| LINK_PROBE | 7 | 1–4076 字节，其余 0 | 第 i 字节为 i & 255 的固定测试数据 | R5 对外声明 |
| INPUT_STATE | 8 | 按下掩码、Ⅰ步数、Ⅱ步数、0 | 掩码、600 ms 期限、两个待处理步数 | R6 候选 |

上位机依据 INFO 的 `capabilities` 启用按钮。R3 返回 `screen`，R6 返回 `screen` 和 `input`。
`input` 配置声明命令 8、P/A/M/E、两个拨轮和 600 ms 期限。步数为 int16 二进制补码，每次 -127 至 127。
回复 `<HHhh>` 为接受的按下掩码、期限、Ⅰ和Ⅱ待处理步数。它确认提交，不代表 UI 已完成该动作。
只有命令 8 续期虚拟按住状态；屏幕或 INFO 不延长期限。电脑必须在按住期间发送续期消息。
控制流程详见[控制说明](controls.md)。

## 回复帧

固定 20 字节头，格式 `<4sBBHIII>`；随后是 payload。

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | 4 bytes | ASCII `D1RM` |
| 4 | u8 | 版本 `1` |
| 5 | u8 | 子命令，必须匹配请求 |
| 6 | u16 | flags：bit 0 为回复，bit 1 为错误，其余必须 0 |
| 8 | u32 | 请求序号 |
| 12 | u32 | payload 字节数，最大 16384 |
| 16 | u32 | payload CRC32，与 zlib.crc32 相同 |

错误 payload 是 UTF-8 文本。头不完整、长度越界、CRC 错误、序号不匹配或错误 flags 均使当前操作失败。
上位机停止连续扫描并显示错误，不把之前的数据当成新数据。
底层驱动可能保留接收缓冲区尾部，解析器仅使用头中指定的长度。

## 屏幕块

16 字节头，格式 `<IHHHHBBH>`。
依次为扫描标识 u32、x/y/宽/高四个 u16、编码 u8、保留 u8、flags u16。
保留字段和 flags 必须为 0。矩形必须在 480 × 320 内，服务端每次最多 512 像素。

- 编码 0：逐行小端 RGB565，每像素 2 字节，长度必须恰好等于宽 × 高 × 2。
- 编码 1：RLE，每项 `<HH>` 表示像素数量和 RGB565 值；数量必须大于 0，各项总和必须恰好填满矩形。当前 C 服务只发送编码 0。

未声明 `screen_stream` 时，上位机按高 8、宽 64 分块，最后一列宽 32。每帧共 320 次请求。
R4 的 INFO 可以声明 `screen_stream: {command: 5, max_rows: 16, encoding: "rle565"}`。
命令 5 不受旧命令的 512 像素限制；每次至多 16 行，仍必须位于 480 × 320 内。
返回宽和起始坐标必须匹配请求，实际行数为 1 至请求行数。客户端从返回矩形的下一行继续。
输出空间不足时回滚整个未完成行，也回滚前一个 RLE 项被本行扩大的长度。
客户端必须检查实际行数，防止不前进、跳行或接受超出请求范围的数据。
同一帧各块标识不一致时拒绝显示。本机候选的标识固定为 0，表示未实现锁存快照；其画面仍可能跨多个显示刷新。
取消操作在块间生效；Windows 单次 SCSI 超时为 12 秒，覆盖原机 AUTO 的长操作。

## 波形

40 字节头，格式 `<IIddffff>`：点数 u32、通道掩码 u32、采样间隔 dt f64、首样本时间 t0 f64，
随后为 A 通道 scale/offset 两个 f32、B 通道 scale/offset 两个 f32。
dt 和 t0 单位为秒。每通道样本为 uint8，按 A、B 通道分别连续排列。
掩码为 1=A、2=B、3=双通道。每次 1–4096 点，长度必须匹配启用通道数。

```text
t[n] = t0 + n * dt
V_ch[n] = uint8_sample_ch[n] * scale_ch + offset_ch
```

scale 和 offset 的单位分别为 V/code 和 V。客户端拒绝非有限元数据和不大于 0 的 dt。
通用 C 回调负责先检查输出缓冲区容量再写入；原生补丁复用 4096 字节缓冲区，当前没有实现波形回调。
如果以后启用原生波形服务，需要实现分块读取、一致快照和可信的缩放系数，再声明 `waveform` 能力。

## 按键与拨轮确认

命令 8 参数是远程按键掩码、拨轮Ⅰ步数、拨轮Ⅱ步数、零。P/A/M/E 分别为位 0/1/2/3。
回复始终为 `<HHhh>`：按键状态字、600 ms 输入期限、两只拨轮的待取出计数。

旧固件的状态字只回报收到的远程掩码。
R11 的 INFO 声明 `input.key_ack="reported-v1"`，此时状态字使用以下位段：

| 位 | 含义 |
| --- | --- |
| 0–3 | 已接收的远程按键 |
| 4–7 | 物理按键保持 |
| 8–11 | 原机按键读取函数已读到的合并状态 |
| 12–15 | 保留，必须为零 |

电脑等待已读状态等于远程与物理状态的并集，再发下一次边沿。物理键仍保持时，电脑松键不会要求物理状态归零。
这确认边沿已被原机读取，不表示 AUTO 等长操作或整个菜单绘制已经完成。
R11 需要客户端 0.5.5 或更新版本；未协商此格式时必须按旧字段解释。

R10 起虚拟拨轮在原机接收者忙时保留，物理拨轮仍优先。电脑不根据丢失回复自动重发拨轮步数。

## 设备侧调度

USB 中断只接收 C0 请求并将 BOT state 标记为 `0x7F`。显示循环复制 CDB，在现有 MSC 缓冲区生成回复，然后调用原厂 DATA-IN 发送函数。
完成阶段 state 1 / 3 继续走原厂 DATA-IN / CSW 逻辑。非 C0 命令保留原分发。
处理过程中若 USB reset 改变状态，或 CDB 已被新请求替换，则取消旧回复。
早期只读屏补丁不分配堆；R7 及后续绘图流按需分配 4–16 KiB 原机堆，停止或期限届满后释放。R11 静态尾部状态为 112 字节。
各版本的实机范围和当前输入回归见 [控制修复记录](controls-regression.md)。

## 绘图流量分析

R5 不发送绘图流，只统计五类原厂绘图入口的调用及预计编码量。命令 6 的 64 字节回复依次为：
magic `0x35505244`、active、epoch、loop_passes、nonempty_passes、points、rectangles、spans、
bitmap_rows、pixels、encoded_bytes、raw_bytes、pass_bytes、peak_pass_bytes、invalid_rectangles、reserved。
各项为小端 u32。action=1 清零并增加 epoch；action=0 停止后返回计数；action=2 不改变启用状态。
非空循环批次不等于独立屏幕刷新或最终镜像帧，计数还没有扣除插桩开销。
预计编码量按点 10 字节、填充矩形 14 字节、像素行 12 字节头加 raw/RLE 较短者计算；每个非空批次另加 8 字节呈现标记。
它不含 SCSI、USB、外层 CRC 或绘图分包的头开销。

命令 7 仅生成固定字节，不读取任意地址或 LCD；其作用是隔离 USB 传输速度与 LCD 反读时间。
`tools/profile_drawing.py` 会先验证固定数据，再运行一个有时间上限的分析窗口，结束时关闭统计。

绘图重放的初始化和丢包规则见 [绘图流](drawing-stream.md)。R7 及后续设备发送 `DRW1`；当前刷新跟随原机，不强制 30 fps。
